# Ofrivo Mobile

This is the Step 0–6 Flutter application source. It contains the fake-data UI, router, Riverpod state providers, Material 3 theme, Email + Password Auth/Profile adapter, customer job creation flow, provider application flow, and Provider Job Feed/Bid flow.

The Android platform folder is intentionally generated by the Flutter toolchain rather than hand-written. Flutter stable 3.44.8 / Dart 3.12.2 is prepared at `F:\Dev\FlutterSDK`; Android licenses are accepted and the user PATH has been updated.

Run from this folder:

```text
flutter create --platforms=android .
flutter pub get
flutter analyze
flutter test
flutter build apk --debug  # demo preview only
```

For account-isolated device testing, do not install an APK built with the plain command above: omitted defines intentionally use FakeAuthRepository. From the repository root, use the configured build helper:

```powershell
.\scripts\local-dev.ps1 -Command apk
```

The helper injects the local Supabase URL (`10.0.2.2:54421` for an emulator) and anon key. To build against Supabase Cloud without committing credentials, set `OFRIVO_SUPABASE_URL` and `OFRIVO_SUPABASE_ANON_KEY` in the current PowerShell process before running the helper. Never pass a service-role key to Flutter.
For a real `ofrivo-dev` connection, pass values at runtime instead of committing them:

```text
flutter run --dart-define=SUPABASE_URL=https://<project-ref>.supabase.co --dart-define=SUPABASE_ANON_KEY=<anon-key> --dart-define=APP_ENV=development
```

If the values are omitted, the app uses local demo mode and does not contact Supabase.

In demo mode, customer jobs are stored in memory for the current run. With runtime Supabase defines, job rows use the authenticated customer and photos upload to the private `job-photos` bucket.

Provider applications use the seeded categories/areas in demo mode. With runtime Supabase defines, identity evidence and work photos upload to the private `provider-verifications` bucket and submission calls the server-side `submit_provider_application` RPC.

Provider mode loads approved-provider jobs from the safe `public_job_feed` view. In demo mode, filters and bid lifecycle changes are held in memory. With runtime Supabase defines, feed photos use short-lived signed URLs, bid edits update only the authenticated provider's pending bid, and withdrawal marks that bid as `withdrawn`.
